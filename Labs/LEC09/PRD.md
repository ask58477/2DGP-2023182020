# Sonic Animation Viewer PRD

## 1. 개요

### 제품
Sonic 스프라이트 시트의 캐릭터 애니메이션을 순서대로 보여주는 Python 데스크톱 애니메이션 뷰어.

### 목적
`sonic-sprite.png`에 포함된 애니메이션 프레임을 개별 동작으로 재생하고, 프레임을 알아보기 쉬운 크기로 확대해 확인할 수 있게 한다.

### 대상 사용자
2D 게임 프로그래밍 실습에서 스프라이트 시트 분리와 프레임 애니메이션을 학습하는 개발자 및 수강생.

## 2. 제품 목표와 제외 범위

### 목표
- 스프라이트 시트에 있는 모든 캐릭터 애니메이션을 빠짐없이 순서대로 재생한다.
- 각 애니메이션을 5회 반복 재생한 뒤 1초 대기하고 다음 애니메이션으로 진행한다.
- 모든 애니메이션을 끝까지 재생하면 첫 애니메이션부터 전체 순서를 무한 반복한다.
- 프레임이 잘리지 않고 명확히 보이도록 확대해서 표시한다.

### 제외 범위
- 애니메이션 선택, 일시정지, 속도 조절 등 사용자 입력 기능
- 스프라이트 시트 편집이나 프레임 좌표를 자동으로 추출하는 기능
- 별도 설정 파일, 에셋 변환 도구, 다중 모듈 구조

## 3. 사용자 시나리오

1. 사용자가 `sonic_animation_viewer.py`를 실행한다.
2. 프로그램이 같은 실습 폴더의 `sonic-sprite.png`를 읽고 뷰어 창을 연다.
3. 첫 애니메이션을 프레임 순서대로 재생한다.
4. 해당 애니메이션 재생을 총 5회 완료한 뒤 1초 대기한다.
5. 다음 애니메이션에 대해 같은 절차를 수행한다.
6. 마지막 애니메이션 뒤에도 1초 대기하고 처음 애니메이션부터 반복한다.

## 4. 기능 요구사항

### FR-1. 실행 파일과 라이브러리
- 실행 진입점은 `Labs/LEC09/sonic_animation_viewer.py` 단일 Python 파일이어야 한다.
- 그래픽 및 이미지 처리는 수업 환경의 Pico2D 라이브러리를 사용한다. PRE-PRD의 `p1co2d` 표기는 `pico2d`를 의미하는 것으로 해석한다.
- 입력 스프라이트 파일명은 `sonic-sprite.png`로 고정한다.

### FR-2. 애니메이션 데이터
- 스프라이트 시트에서 확인되는 모든 논리적 캐릭터 동작을 애니메이션으로 정의한다.
- 각 애니메이션은 프레임의 스프라이트 시트 좌표와 원본 크기를 사용해 정확히 잘라낸다.
- 한 애니메이션의 프레임은 의도한 동작 순서대로 표시한다.
- 시트의 제목, 설명 문구, 크레딧 및 장식용 단독 이미지는 애니메이션에 포함하지 않는다.

### FR-3. 프레임 재생
- 애니메이션의 프레임을 순환하며 재생한다.
- 각 애니메이션을 연속으로 정확히 5회 재생한다.
- 다섯 번째 재생이 끝난 후 1초간 대기한 다음 다음 애니메이션을 시작한다.
- 모든 애니메이션 재생이 끝난 후에도 1초 대기 규칙을 적용하고 전체 순서를 처음부터 반복한다.
- 프레임 전환 중 이전 프레임의 잔상이 남지 않도록 화면을 갱신한다.

### FR-4. 화면 표시
- 프레임은 원본 비율을 유지해 확대하고, 화면 안에서 전체 캐릭터가 보이도록 한다.
- 첫 두 달리기 애니메이션은 화면 안에서 좌우로 이동하며, 이동 가능 영역 끝에 닿으면 방향을 바꾼다.
- 이동 애니메이션이 아닌 동작은 화면 중앙에 표시한다.
- 왼쪽으로 이동할 때는 캐릭터 이미지도 이동 방향을 향하도록 반전한다.
- 투명 배경은 유지한다.

### FR-5. 에셋 경로
- `sonic-sprite.png`는 실행에 필요한 필수 입력 파일이다.
- 사용자는 프로젝트의 `Labs/LEC09` 폴더에서 프로그램을 실행할 수 있어야 한다.
- 입력 파일을 찾지 못하는 경우 원인을 식별할 수 있도록 오류를 출력한다.

## 5. 비기능 요구사항 및 제약

- 구현은 `sonic_animation_viewer.py` 한 파일 안에 둔다.
- 별도 패키지 설치가 필요하다면 Pico2D 외 추가 의존성은 도입하지 않는다.
- 애니메이션 순서는 스프라이트 시트의 위에서 아래, 각 행에서는 왼쪽에서 오른쪽을 기본으로 한다. 명확히 분리된 동작 그룹은 그룹 단위로 순서를 정한다.
- 반복 횟수, 대기 시간, 배율 및 프레임 좌표는 코드에서 쉽게 확인하고 수정할 수 있어야 한다.
- 종료 동작은 Pico2D 창의 기본 종료 방식과 충돌하지 않아야 한다.

## 6. 수용 기준

- [ ] `Labs/LEC09/sonic_animation_viewer.py`가 단독 실행 진입점으로 존재한다.
- [ ] 프로그램이 `sonic-sprite.png`를 로드하고 창에 캐릭터를 표시한다.
- [ ] 스프라이트 시트의 모든 논리적 캐릭터 애니메이션이 재생되며, 제목·크레딧·장식 이미지는 재생되지 않는다.
- [ ] 각 애니메이션의 프레임이 의도한 순서로 반복된다.
- [ ] 각 애니메이션은 정확히 5회 재생된 다음 1초 대기한다.
- [ ] 다음 애니메이션으로 순차 진행하며 마지막 동작 다음에는 처음부터 다시 시작한다.
- [ ] 창을 열어 둔 동안 전체 애니메이션 사이클이 중단 없이 반복된다.
- [ ] 확대된 캐릭터의 프레임이 잘리지 않고 투명 배경과 원본 비율을 유지한다.
- [ ] 첫 두 달리기 동작은 실제 화면 좌우로 이동하고, 안전 영역에서 방향을 바꾸며 캐릭터가 잘리지 않는다.
- [ ] 이동하지 않는 동작은 화면 중앙에 표시된다.
- [ ] 에셋 파일이 없는 경우 파일명 또는 경로를 포함한 오류 원인을 확인할 수 있다.

## 7. 구현 전 확인사항

- 스프라이트 시트의 각 동작별 프레임 경계, 좌표, 프레임 수를 확인하고 애니메이션 목록을 확정한다.
- PRE-PRD에 재생 속도와 확대 배율이 수치로 지정되어 있지 않다. 구현 시 모든 애니메이션에 일관된 프레임 간격과 알아보기 쉬운 배율을 적용한다.
- Pico2D가 설치된 수업 실행 환경에서 창 종료 및 리소스 경로 동작을 확인한다.

## 8. 개발 단계 및 커밋 기준

전체 개발은 최소 20개의 의미 있는 커밋으로 나눈다. 각 커밋은 실행 가능하거나 확인 가능한 작은 변경을 담고, 단순 분할을 위한 빈 커밋은 만들지 않는다. 
추가로 커밋 메세지는 반드시 한글로 작성한다.

1. 단일 파일과 실행 진입점 생성
2. Pico2D import 및 창 초기화
3. 창 종료와 기본 화면 갱신 확인
4. 스프라이트 이미지 로드
5. 에셋 누락 오류 동작 확인
6. 프레임 좌표 데이터 형식 정의
7. 첫 번째 동작의 프레임 좌표 등록
8. 단일 프레임 클리핑 출력
9. 첫 번째 동작의 프레임 순환 재생
10. 프레임 간격을 일정하게 적용
11. 프레임 잔상 제거 및 화면 갱신 적용
12. 캐릭터 위치와 확대 크기 조정
13. 다음 동작 그룹의 프레임 좌표 등록
14. 남은 동작 그룹의 프레임 좌표 등록
15. 시트 장식 요소가 동작 데이터에 포함되지 않도록 확인
16. 애니메이션 목록 순차 실행
17. 애니메이션별 5회 반복 적용
18. 동작 사이 1초 대기 적용
19. 전체 애니메이션 순환 반복 적용
20. 좌표, 순서, 잘림 및 투명 배경 최종 검수
21. 깨끗한 실행 및 반복 사이클 수동 검증

## 9. 검증 방법

- Pico2D가 설치된 환경에서 `Labs/LEC09`를 작업 디렉터리로 하여 프로그램을 실행한다.
- 스프라이트 시트와 뷰어 출력을 나란히 비교해 프레임 경계와 그룹별 순서를 확인한다.
- 최소 두 번의 전체 사이클을 관찰해 동작당 5회 재생, 동작 사이 1초 대기, 마지막부터 처음으로의 순환을 확인한다.
- 확대 출력에서 프레임 누락, 잘림, 잔상, 비율 왜곡 및 원치 않는 시트 문구 노출 여부를 확인한다.
- 스프라이트 파일이 없는 경우를 확인해 오류가 원인을 알아볼 수 있게 안내하는지 검증한다.
